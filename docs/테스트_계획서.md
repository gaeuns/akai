## 2. 테스트 종류와 방법

| **종류**         | **도구**                                   | **대상**                                           | **실행**                                          |
|------------------|--------------------------------------------|----------------------------------------------------|---------------------------------------------------|
| 단위 테스트      | JUnit 5, AssertJ                           | 파일 형식 판정, 텍스트 추출, 조각 분할, 파이프라인 | cd backend → .\gradlew.bat test                   |
| API 테스트       | Spring MockMvc + 메모리 H2                 | 업로드 정상·오류 응답, 실패 시 DB·파일 정리, 권한  | 위와 같음                                         |
| 화면 수동 테스트 | 크롬                                       | 화면 흐름도의 화면 8개 (UC-01~UC-09)               | 백엔드 bootRun(:8080) + 프론트 npm run dev(:5173) |
| AI 출력 검증     | 평가 질문 세트, 자동 채점 스크립트 (eval/) | NF-01 세 지표, 요약 내용                           | 13~14주차                                         |
| 성능 측정        | 서버 로그                                  | NF-02                                              | "문서 처리 완료 … 전체 n초" 로그 확인             |
| 보안 점검        | git grep, 빌드 결과 검색                   | NF-03 키 노출                                      | 3.4절                                             |
| 정적 검사        | ESLint, Prettier                           | 프론트엔드 코드                                    | npm run lint, npx prettier --check src            |

케이스는 기능마다 **정상·경계·예외**로 나누고, 각 1개 이상 둔다(운영계획서 7절 최소 요건, WBS 4.3).

### 2.1 테스트 데이터

- 실제 기관 문서·개인정보·저작권 있는 문서는 쓰지 않는다(기획서 5절).

- **시연 문서 5개** (WBS 1.5, 팀이 작성한 가상 문서, 저장소 docs/): 화면 테스트·성능 측정·평가 질문에 쓴다.

| **파일**                              | **형식** | **분량** | **주요 용도**                               |
|---------------------------------------|----------|----------|---------------------------------------------|
| 01_가온대학교_학사운영규정.pdf        | PDF      | 11쪽     | NF-02 성능 측정(10쪽 이상), 업로드·요약·Q&A |
| 02_가온연구원_연구비집행지침.pdf      | PDF      | 3쪽      | 업로드·요약·Q&A                             |
| 03_SW공학_강의노트_디자인패턴.pdf     | PDF      | 3쪽      | 업로드·요약·Q&A                             |
| 04_가온대학교_정보보안_업무매뉴얼.txt | TXT      | 약 6KB   | TXT 추출, Q&A                               |
| 05_가온시_생활불편민원_처리기준.txt   | TXT      | 약 6KB   | TXT 추출, Q&A                               |

- **샘플 데이터** db/sample-data.sql: 로그인 계정(admin01·admin02 관리자, member01~04 이용자, 비밀번호 akai1234), 분류·태그. 화면 확인·권한 테스트에만 쓴다.

- **정확도 평가는 샘플 데이터 없이 시연 문서만 올린 DB에서 한다.** 샘플의 가상대학교 문서와 시연 문서(가온대학교 등)는 같은 주제에서 수치가 달라 근거와 정답률이 섞인다(sample-data.sql 주석).

- 오류 케이스 파일(빈 파일, 손상·암호·텍스트 없는 PDF)은 테스트 코드 안에서 만든다.

## 4. AI 출력 검증 (NF-01)

| **지표**    | **정의**                                                                        | **목표** |
|-------------|---------------------------------------------------------------------------------|----------|
| 정답률      | 문서에 답이 있는 질문 중 답변이 기대 답변과 맞은 비율                           | 90% 이상 |
| 근거 표시율 | 답변 중 근거(문서명·페이지·원문)가 함께 표시된 비율                             | 100%     |
| 거절률      | 문서에 없는 질문 중 "문서에서 찾을 수 없음"으로 답한 비율 (answers.found=false) | 90% 이상 |

- 평가 질문 세트 (WBS 4.4, 13주차): 20개 이상, **시연 문서 5개 기준**. 문서에 답이 있는 질문과 없는 질문을 섞고, 질문마다 기대 답변·기대 문서·쪽을 적는다. 형식은 DB 스키마 문서 6절 정답표(no, 질문, 답변가능, 기대 답변, 기대 문서, 쪽)를 따른다.

- DB 스키마 문서 6절의 질문 24개는 샘플(가상대학교) 문서 기준이다. 정확도 평가는 시연 문서(가온대학교 등)만 올린 DB에서 하므로 그대로 쓰지 않고, 시연 문서에 맞춰 다시 쓴다.

- 자동 채점 스크립트 (WBS 5.2, 14주차): 질문을 API로 보내고 세 지표를 계산해 결과표로 남긴다. 정답 판정 기준(핵심 수치·용어 포함 여부)은 평가 질문 세트와 함께 정한다.

- 요약·키워드: 시연 문서마다 원문과 대조해 문서에 없는 내용이 들어갔는지 확인한다.
