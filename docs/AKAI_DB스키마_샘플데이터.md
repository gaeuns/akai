# AKAI DB 스키마 및 샘플 데이터

공공·연구·교육기관용 문서 요약 및 Q&A 지식베이스 · 시스템 설계서 8절 ERD 기준

## 1. 개요

- 시스템 설계서 8절 ERD(테이블 10개)를 그대로 SQL로 옮겼다. DB는 H2(파일 모드)를 기준으로 한다.

- 주제 안내서의 주요 데이터(Document, Chunk, Summary, Tag, Question, Answer)를 모두 테이블로 만들고, 다대다 관계 2개(문서-태그, 답변-근거 조각)는 연결 테이블로 풀었다.

- 샘플 데이터는 모두 가상이다. 실제 개인정보·기관 문서·저작권 자료를 쓰지 않았고, 문서 내용은 직접 작성했다.

- 모든 계정의 비밀번호는 akai1234이며 DB에는 BCrypt 해시로 저장한다.

- 적재 순서는 부록 A(schema.sql) → 부록 B(data.sql)이다.

## 3. 관계와 삭제 규칙

클래스 다이어그램의 구성·집합 구분을 삭제 규칙에 반영했다. 구성은 전체가 지워지면 부분도 함께 지워지고, 집합은 부분이 따로 남는다. FK에는 ON DELETE를 두지 않고, 구성 관계의 삭제는 JPA cascade(cascade = ALL, orphanRemoval)가, 집합 관계(분류·태그)는 서비스가 처리한다.

| 관계                                 | 유형 | 삭제 규칙                  | 의미                                    |
|:-------------------------------------|:-----|:---------------------------|:----------------------------------------|
| documents 1 — N chunks               | 구성 | JPA cascade                | 문서를 지우면 조각도 함께 삭제          |
| documents 1 — 1 summaries            | 구성 | JPA cascade                | 문서를 지우면 요약도 함께 삭제          |
| questions 1 — 1 answers              | 구성 | JPA cascade                | 질문을 지우면 답변도 함께 삭제          |
| answers 1 — N answer_evidences       | 구성 | 질문 삭제에 따라 함께 삭제 | 답변의 근거 연결 행 삭제                |
| chunks 1 — N answer_evidences        | 연관 | 서비스에서 연결 행 삭제    | 조각이 삭제되면 근거 연결 행도 삭제     |
| categories 1 — N documents           | 집합 | 서비스에서 분류 비움       | 분류를 지워도 문서는 남고 분류만 비워짐 |
| documents N — M tags (document_tags) | 집합 | 연결 행만 삭제             | 태그·문서는 각자 존속                   |
| users 1 — N documents (uploaded_by)  | 연관 | RESTRICT(기본)             | 문서를 올린 관리자는 삭제 불가          |
| users 1 — N questions                | 연관 | RESTRICT(기본)             | 질문 이력이 있는 사용자는 삭제 불가     |

## 4. 테이블 정의서

### 4.1 users

이용자·관리자 계정. 상속(Member·Admin)을 단일 테이블 + role 구분 컬럼으로 저장 (관련 기능: F-08, NF-03)

| 컬럼          | 타입         | 키  | 제약                                  | 설명                                     |
|:--------------|:-------------|:---:|:--------------------------------------|:-----------------------------------------|
| id            | BIGINT       | PK  | AUTO_INCREMENT                        | 사용자 식별자                            |
| login_id      | VARCHAR(50)  | UK  | NOT NULL                              | 로그인 ID                                |
| password_hash | VARCHAR(100) |     | NOT NULL                              | BCrypt 해시(평문 저장 금지)              |
| name          | VARCHAR(50)  |     | NOT NULL                              | 이름                                     |
| role          | VARCHAR(10)  |     | NOT NULL, CHECK IN ('MEMBER','ADMIN') | 권한. 관리자 API는 서버에서 이 값을 검사 |

### 4.2 categories

문서 분류. 분류가 삭제돼도 문서는 남는다(집합) (관련 기능: F-04)

| 컬럼 | 타입        | 키  | 제약           | 설명        |
|:-----|:------------|:---:|:---------------|:------------|
| id   | BIGINT      | PK  | AUTO_INCREMENT | 분류 식별자 |
| name | VARCHAR(50) | UK  | NOT NULL       | 분류명      |

### 4.3 tags

문서 태그. 문서와 N:M (관련 기능: F-04)

| 컬럼 | 타입        | 키  | 제약           | 설명        |
|:-----|:------------|:---:|:---------------|:------------|
| id   | BIGINT      | PK  | AUTO_INCREMENT | 태그 식별자 |
| name | VARCHAR(50) | UK  | NOT NULL       | 태그명      |

### 4.4 documents

업로드된 문서의 메타데이터와 처리 상태 (관련 기능: F-01, F-04)

| 컬럼        | 타입         | 키  | 제약                                                                              | 설명                                      |
|:------------|:-------------|:---:|:----------------------------------------------------------------------------------|:------------------------------------------|
| id          | BIGINT       | PK  | AUTO_INCREMENT                                                                    | 문서 식별자                               |
| title       | VARCHAR(200) |     | NOT NULL                                                                          | 문서 제목                                 |
| file_name   | VARCHAR(255) |     | NOT NULL                                                                          | 업로드 원본 파일명                        |
| file_type   | VARCHAR(10)  |     | NOT NULL, CHECK IN ('PDF','TXT')                                                  | 파일 형식(TextExtractorFactory 선택 기준) |
| status      | VARCHAR(20)  |     | NOT NULL, DEFAULT 'UPLOADED', CHECK IN ('UPLOADED','PROCESSING','READY','FAILED') | 파이프라인 처리 상태                      |
| category_id | BIGINT       | FK  | NULL 허용                                                                         | → categories.id                           |
| uploaded_by | BIGINT       | FK  | NULL 허용                                                                         | → users.id (업로드한 관리자)              |
| created_at  | TIMESTAMP    |     | NOT NULL, DEFAULT CURRENT_TIMESTAMP                                               | 업로드 일시                               |

### 4.5 chunks

문서를 분할한 조각. 검색과 근거 표시의 단위(구성: 문서 삭제 시 함께 삭제) (관련 기능: F-01, F-03)

| 컬럼        | 타입             | 키  | 제약                               | 설명                                         |
|:------------|:-----------------|:---:|:-----------------------------------|:---------------------------------------------|
| id          | BIGINT           | PK  | AUTO_INCREMENT                     | 조각 식별자                                  |
| document_id | BIGINT           | FK  | NOT NULL                           | → documents.id                               |
| page_no     | INT              |     | NOT NULL, CHECK \>= 1              | 원문 페이지. TXT는 전체를 1페이지로 본다     |
| seq         | INT              |     | NOT NULL, UNIQUE(document_id, seq) | 문서 안 조각 순서                            |
| content     | VARCHAR(10000)   |     | NOT NULL                           | 조각 원문                                    |
| embedding   | VARBINARY(16384) |     | NULL 허용                          | F-06 임베딩(float 배열). 처음 검색할 때 계산 |

### 4.6 summaries

문서별 AI 요약과 핵심 키워드. 업로드 때 한 번만 생성(문서와 1:1, 구성) (관련 기능: F-02)

| 컬럼         | 타입         |   키   | 제약                                | 설명                                                          |
|:-------------|:-------------|:------:|:------------------------------------|:--------------------------------------------------------------|
| id           | BIGINT       |   PK   | AUTO_INCREMENT                      | 요약 식별자                                                   |
| document_id  | BIGINT       | FK, UK | NOT NULL                            | → documents.id (1:1)                                          |
| content      | TEXT         |        | NOT NULL                            | 요약문                                                        |
| keywords     | VARCHAR(500) |        | NULL 허용                           | 핵심 키워드(쉼표 구분)                                        |
| ai_generated | BOOLEAN      |        | NOT NULL, DEFAULT TRUE              | AI 생성 여부. 관리자가 수정하면 FALSE(AI 생성 배지 표시 기준) |
| updated_at   | TIMESTAMP    |        | NOT NULL, DEFAULT CURRENT_TIMESTAMP | 생성·수정 일시                                                |

### 4.7 document_tags

문서와 태그의 N:M 연결 테이블 (관련 기능: F-04)

| 컬럼        | 타입   |   키   | 제약 | 설명           |
|:------------|:-------|:------:|:-----|:---------------|
| document_id | BIGINT | PK, FK |      | → documents.id |
| tag_id      | BIGINT | PK, FK |      | → tags.id      |

### 4.8 questions

이용자가 한 질문 이력 (관련 기능: F-05, F-07)

| 컬럼            | 타입      | 키  | 제약                                | 설명                    |
|:----------------|:----------|:---:|:------------------------------------|:------------------------|
| id              | BIGINT    | PK  | AUTO_INCREMENT                      | 질문 식별자             |
| user_id         | BIGINT    | FK  | NOT NULL                            | → users.id (질문자)     |
| content         | TEXT      |     | NOT NULL                            | 질문 내용               |
| asked_at        | TIMESTAMP |     | NOT NULL, DEFAULT CURRENT_TIMESTAMP | 질문 일시               |
| response_millis | BIGINT    |     | NULL 허용                           | F-09 검색\~답변 시간(ms) |

### 4.9 answers

질문에 대한 답변(질문과 1:1, 구성) (관련 기능: F-03)

| 컬럼        | 타입    |   키   | 제약           | 설명                                                     |
|:------------|:--------|:------:|:---------------|:---------------------------------------------------------|
| id          | BIGINT  |   PK   | AUTO_INCREMENT | 답변 식별자                                              |
| question_id | BIGINT  | FK, UK | NOT NULL       | → questions.id (1:1)                                     |
| content     | TEXT    |        | NOT NULL       | 답변 내용                                                |
| found       | BOOLEAN |        | NOT NULL       | FALSE면 "문서에서 찾을 수 없음" 응답. 거절률 측정에 사용 |

### 4.10 answer_evidences

답변과 근거 조각의 N:M 연결 테이블. 근거의 문서명·페이지는 chunks → documents로 얻는다 (관련 기능: F-03, F-05)

| 컬럼      | 타입   |   키   | 제약 | 설명         |
|:----------|:-------|:------:|:-----|:-------------|
| answer_id | BIGINT | PK, FK |      | → answers.id |
| chunk_id  | BIGINT | PK, FK |      | → chunks.id  |

## 부록 A. schema.sql

```sql
-- AKAI DB 스키마 (시스템 설계서 8절 ERD, 테이블 10개) / H2 기준
-- 엔티티(backend/.../domain)와 enum 값·테이블·컬럼명을 맞춘 참조용 SQL이다.
-- 개발 중에는 JPA ddl-auto=update가 테이블을 만들므로, 이 파일은 DB를 비운 뒤 직접 실행할 때 쓴다.
-- 삭제 규칙: FK에는 ON DELETE를 두지 않는다.
--           구성 관계(문서→조각·요약, 질문→답변)의 삭제는 JPA cascade(cascade = ALL, orphanRemoval)가 처리하고,
--           집합 관계(분류·태그)는 서비스에서 처리한다.

-- 주의: 아래 DROP TABLE은 기존 테이블과 데이터를 모두 지운다. 개발 DB에 그대로 실행하면 데이터가 모두 삭제된다.

DROP TABLE IF EXISTS answer_evidences;
DROP TABLE IF EXISTS answers;
DROP TABLE IF EXISTS questions;
DROP TABLE IF EXISTS document_tags;
DROP TABLE IF EXISTS tags;
DROP TABLE IF EXISTS summaries;
DROP TABLE IF EXISTS chunks;
DROP TABLE IF EXISTS documents;
DROP TABLE IF EXISTS categories;
DROP TABLE IF EXISTS users;

CREATE TABLE users (
    id            BIGINT AUTO_INCREMENT PRIMARY KEY,
    login_id      VARCHAR(50)  NOT NULL UNIQUE,
    password_hash VARCHAR(100) NOT NULL,              -- BCrypt
    name          VARCHAR(50)  NOT NULL,
    role          VARCHAR(10)  NOT NULL,              -- 상속(Member/Admin)을 단일 테이블+구분 컬럼으로 저장
    CONSTRAINT ck_users_role CHECK (role IN ('MEMBER', 'ADMIN'))
);

CREATE TABLE categories (
    id   BIGINT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(50) NOT NULL UNIQUE
);

CREATE TABLE tags (
    id   BIGINT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(50) NOT NULL UNIQUE
);

CREATE TABLE documents (
    id          BIGINT AUTO_INCREMENT PRIMARY KEY,
    title       VARCHAR(200) NOT NULL,
    file_name   VARCHAR(255) NOT NULL,
    file_type   VARCHAR(10)  NOT NULL,
    status      VARCHAR(20)  NOT NULL DEFAULT 'UPLOADED',     -- 파이프라인 진행 상태(DocumentStatus enum과 동일)
    category_id BIGINT,
    uploaded_by BIGINT,                                       -- 업로드한 관리자(로그인 F-08 구현 전에는 NULL 허용)
    created_at  TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT ck_documents_file_type CHECK (file_type IN ('PDF', 'TXT')),
    CONSTRAINT ck_documents_status    CHECK (status IN ('UPLOADED', 'PROCESSING', 'READY', 'FAILED')),
    CONSTRAINT fk_documents_category  FOREIGN KEY (category_id) REFERENCES categories (id),
    CONSTRAINT fk_documents_uploader  FOREIGN KEY (uploaded_by) REFERENCES users (id)
);

CREATE TABLE chunks (
    id          BIGINT AUTO_INCREMENT PRIMARY KEY,
    document_id BIGINT  NOT NULL,
    page_no     INT     NOT NULL,                             -- TXT는 전부 1페이지
    seq         INT     NOT NULL,                             -- 문서 안에서의 조각 순서
    content     VARCHAR(10000) NOT NULL,                      -- CLOB은 upper() 검색이 안 되어 VARCHAR 사용
    embedding   VARBINARY(16384),                             -- F-06 임베딩(float 배열). 처음 검색할 때 계산
    CONSTRAINT uq_chunks_doc_seq UNIQUE (document_id, seq),
    CONSTRAINT ck_chunks_page    CHECK (page_no >= 1),
    CONSTRAINT fk_chunks_document FOREIGN KEY (document_id) REFERENCES documents (id)
);

CREATE TABLE summaries (
    id           BIGINT AUTO_INCREMENT PRIMARY KEY,
    document_id  BIGINT       NOT NULL UNIQUE,                -- 문서와 1:1
    content      TEXT         NOT NULL,
    keywords     VARCHAR(500),                                -- 쉼표로 구분
    ai_generated BOOLEAN      NOT NULL DEFAULT TRUE,          -- 관리자가 수정하면 FALSE
    updated_at   TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT fk_summaries_document FOREIGN KEY (document_id) REFERENCES documents (id)
);

CREATE TABLE document_tags (
    document_id BIGINT NOT NULL,
    tag_id      BIGINT NOT NULL,
    PRIMARY KEY (document_id, tag_id),
    CONSTRAINT fk_dt_document FOREIGN KEY (document_id) REFERENCES documents (id),
    CONSTRAINT fk_dt_tag      FOREIGN KEY (tag_id)      REFERENCES tags (id)
);

CREATE TABLE questions (
    id       BIGINT AUTO_INCREMENT PRIMARY KEY,
    user_id  BIGINT    NOT NULL,
    content  TEXT      NOT NULL,
    asked_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    response_millis BIGINT,                                   -- F-09 검색~답변 시간(ms)
    CONSTRAINT fk_questions_user FOREIGN KEY (user_id) REFERENCES users (id)
);

CREATE TABLE answers (
    id          BIGINT AUTO_INCREMENT PRIMARY KEY,
    question_id BIGINT  NOT NULL UNIQUE,                      -- 질문과 1:1
    content     TEXT    NOT NULL,
    found       BOOLEAN NOT NULL,                             -- FALSE = "문서에서 찾을 수 없음" (거절률 측정)
    CONSTRAINT fk_answers_question FOREIGN KEY (question_id) REFERENCES questions (id)
);

CREATE TABLE answer_evidences (
    answer_id BIGINT NOT NULL,
    chunk_id  BIGINT NOT NULL,
    PRIMARY KEY (answer_id, chunk_id),
    CONSTRAINT fk_ae_answer FOREIGN KEY (answer_id) REFERENCES answers (id),
    CONSTRAINT fk_ae_chunk  FOREIGN KEY (chunk_id)  REFERENCES chunks (id)
);

CREATE INDEX idx_documents_category ON documents (category_id);
CREATE INDEX idx_documents_uploader ON documents (uploaded_by);
CREATE INDEX idx_questions_user     ON questions (user_id, asked_at);
CREATE INDEX idx_dt_tag             ON document_tags (tag_id);
CREATE INDEX idx_ae_chunk           ON answer_evidences (chunk_id);
```
