# 프로젝트 기획서

기관 문서를 올리면 AI가 요약하고, 문서 내용을 근거로만 질문에 답하는 웹 지식베이스를 5주 안에 만든다.

## 1. 프로젝트 개요

| 항목        | 내용                                                                   |
|-------------|------------------------------------------------------------------------|
| 과제명      | 공공·연구·교육기관용 문서 요약 및 Q&A 지식베이스 (과제 10)             |
| 팀명        | 타닥타닥                                                               |
| 서비스명    | AKAI                                                                   |
| 이름의 의미 | Archive(기관 문서의 축적) + AI(문서를 읽고 요약하고 답변하는 인공지능) |
| 팀 구성     | 임성용, 최가은, 김원정                                                 |
| 수행 기간   | 2026.10.27 ~ 11.30 (5주), 최종 발표 12.1                               |
| 시스템 형태 | 웹 애플리케이션                                                        |

## 2. 배경 및 문제 정의

기관에는 규정, 매뉴얼, 논문이 계속 쌓이지만 필요한 내용을 찾으려면 문서를 하나씩 열어 확인해야 한다. 키워드 검색은 표현이 조금만 달라도 찾지 못하고, 일반 챗봇은 문서에 없는 내용을 지어낼 수 있어 업무에 그대로 쓰기 어렵다.

- **문제 1**: 문서가 많을수록 원하는 내용을 찾는 시간이 길어진다.

- **문제 2**: 긴 문서의 핵심을 파악하려면 전체를 읽어야 한다.

- **문제 3**: 생성형 AI의 답변은 근거를 확인할 수 없어 신뢰하기 어렵다.

## 3. 대상 사용자

| 사용자      | 설명                 | 주요 요구                                            |
|-------------|----------------------|------------------------------------------------------|
| 문서 이용자 | 교직원, 연구원, 학생 | 문서 검색, 요약 확인, 질문하고 근거와 함께 답변 받기 |
| 문서 관리자 | 부서 담당자          | 문서 업로드, 분류·태그 관리, 문서 삭제               |

## 4. 프로젝트 목표

1.  문서를 올리면 30초 안에 요약과 핵심 키워드를 제공한다.

2.  모든 답변에 근거 문서와 위치를 표시하고, 근거가 없으면 "문서에서 찾을 수 없음"으로 응답한다.

3.  정답이 정해진 질문 20개 이상으로 답변 정확도를 측정해 90% 이상을 달성한다.

## 5. MVP 범위

| 구분        | 포함                                                                                                          |
|-------------|---------------------------------------------------------------------------------------------------------------|
| 필수 (MVP)  | 문서 업로드·텍스트 추출·분할 저장, AI 요약·키워드, 근거 기반 Q&A, 분류·태그·검색, 질의 이력, 로그인·역할 구분 |
| 확장 (선택) | 임베딩 기반 의미 검색(RAG), 여러 문서 비교 요약, 문서 기반 퀴즈 생성                                          |
| 제외        | 실제 기관 문서·개인정보, 저작권이 있는 문서, 회원가입(계정은 미리 등록)·SSO 연동                              |

MVP는 키워드 검색으로 먼저 완성하고, 남는 시간에 임베딩 검색을 Strategy 패턴으로 추가한다.

## 7. 팀 구성 및 역할

| 공식 역할 | 담당 팀원 | 담당 업무                                                                                       |
|-----------|-----------|-------------------------------------------------------------------------------------------------|
| 팀장(PM)  | 임성용    | 일정·WBS 관리, 주간 스탠드업 진행, 진행 일지·산출물 제출 총괄                                   |
| 설계·문서 | 임성용    | 요구사항 정의서, 시스템 설계서(아키텍처·클래스·ERD·시퀀스), 결과보고서                          |
| 개발      | 최가은    | CLAUDE.md·코딩 규칙 관리, F-01~F-05 구현, OpenAI·DB 연동                                        |
| 검증      | 김원정    | 테스트 계획·케이스 실행, 시연용 문서·평가 질문 세트, 답변 정확도 측정, AI 활용 로그·검증 보고서 |

발표 질의응답은 전원이 답해야 하므로 매주 스탠드업에서 담당 부분을 서로 설명한다.

## 8. 적용 예정 설계 요소

- **아키텍처**: 전체는 3계층 구조, 문서 처리는 업로드 → 추출 → 분할 → 요약 → 저장의 파이프-필터 구조

- **디자인 패턴**: Factory Method(파일 형식별 추출기), Strategy(검색 방식 교체), Adapter(OpenAI·PDF 라이브러리)

- **핵심 품질 속성**: 정확성(근거 기반 답변), 성능(문서 처리 시간)

## 9. 기대 효과

- 문서 이용자는 문서를 열지 않고도 요약과 답변으로 필요한 내용을 빠르게 찾는다.

- 모든 답변에 근거가 붙어 AI 답변을 사람이 바로 확인할 수 있다.
