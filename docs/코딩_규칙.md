# AKAI 팀 코딩 규칙

| 항목 | 내용 |
| --- | --- |
| 문서 상태 | 확정 (팀원 3명 PR 승인으로 확정) |
| 기준 | 수업 ch08 코드 작성 규칙 + 10~12주차에 팀이 실제로 써 온 관례 |
| 적용 범위 | `backend/`, `frontend/`, 커밋·PR, AI 코딩 도구(CLAUDE.md) |
| 관련 WBS | 3.1 팀 코딩 규칙 문서화, CLAUDE.md 반영 |

규칙을 바꾸려면 이 문서를 고치는 PR을 올리고 팀원 전원 승인을 받는다. CLAUDE.md의 코딩 규칙 절도 같은 PR에서 함께 고친다.

---

## 1. 공통

- 들여쓰기는 스페이스로 한다. Java 4칸, JavaScript·CSS·JSON 2칸 (`.editorconfig`로 고정).
- 파일 인코딩은 UTF-8이다. 줄바꿈은 Git이 OS에 맞게 바꾸므로 신경 쓰지 않는다.
- 이름만 보고 역할을 알 수 있게 짓는다. `tmp`, `data2`, `doc` 같은 약어·숫자 이름을 쓰지 않는다.
- 주석은 "무엇을"보다 "왜"를 쓴다. 클래스에는 역할을 한 줄로 설명하는 주석을 단다.
- 아직 구현하지 않은 부분은 `// TODO(F-03): 할 일`처럼 기능 ID를 붙인다. 구현하면 지운다.
- API 키·비밀번호 같은 비밀 값은 코드·설정 파일·프론트엔드에 쓰지 않는다. 서버의 `.env`로만 읽는다.

## 2. Java (backend)

### 2.1 이름

| 대상 | 규칙 | 예 |
| --- | --- | --- |
| 패키지 | 소문자 | `com.tadak.akai.pipeline` |
| 클래스·인터페이스·record | PascalCase, 명사 | `DocumentService`, `SearchStrategy` |
| 메서드 | camelCase, 동사로 시작 | `upload()`, `findById()` |
| 변수·필드 | camelCase | `uploadDir`, `chunkSplitter` |
| 상수 | UPPER_SNAKE_CASE, `static final` | `MAX_CONTENT_LENGTH` |
| 인터페이스 구현 | 무엇을 감싸는지 드러낸다 | `PdfTextExtractor`, `OpenAiAdapter` |

### 2.2 형식

- 중괄호는 선언과 같은 줄에서 연다. `if`·`for` 본문이 한 줄이어도 중괄호를 쓴다.
- 한 줄은 120자 이내로 쓴다. 넘으면 연산자·쉼표 뒤에서 줄을 바꾸고 8칸 들여 쓴다.
- `import`는 하나씩 쓴다. `*` 와일드카드 import를 쓰지 않는다.
- 메서드 하나는 한 가지 일만 한다(SRP). 30줄을 넘으면 나눌 수 있는지 먼저 본다.

### 2.3 구조 (설계서와 CLAUDE.md의 아키텍처를 따른다)

- 계층: `controller` → `service` → `repository`. Controller는 요청·응답 변환과 권한 검사만 하고, 로직은 Service에 둔다.
- 의존성은 **생성자 주입**으로 받고 필드는 `private final`로 둔다. `@Autowired` 필드 주입을 쓰지 않는다.
- 상위 계층은 extractor·search·ai 패키지의 **인터페이스**에만 의존한다. 구현 클래스를 직접 `new` 하지 않는다.
- 새 파일 형식·검색 방식·AI 제공자는 기존 클래스를 고치지 않고 인터페이스의 새 구현으로 추가한다(OCP).
- 엔티티를 API 응답으로 그대로 내보내지 않는다. `dto` 패키지의 record로 바꿔서 내보낸다.
- 트랜잭션: Service 클래스에 `@Transactional(readOnly = true)`, 쓰기 메서드에만 `@Transactional`을 붙인다. 체크 예외에도 롤백해야 하면 `rollbackFor`를 명시한다.
- Lombok은 쓰지 않는다. 생성자·getter는 직접 쓴다.

### 2.4 예외와 오류 응답

- 사용자가 고칠 수 있는 입력 오류는 `IllegalArgumentException`, 없는 대상은 `NoSuchElementException`을 던진다.
- 예외를 HTTP 응답으로 바꾸는 일은 `ApiExceptionHandler` 한 곳에서만 한다. 응답 형식은 `{"message": "..."}`이다.
- 예외 메시지는 사용자가 읽을 한국어 문장으로 쓴다. 예: "지원하지 않는 파일 형식입니다. PDF 또는 TXT만 올릴 수 있습니다."
- 예외를 잡아서 아무것도 안 하고 넘기지 않는다. 넘겨도 되는 경우(요약 실패 등)는 로그를 남기고 이유를 주석으로 쓴다.

### 2.5 로그

- SLF4J(`LoggerFactory.getLogger`)를 쓴다. `System.out.println`을 쓰지 않는다.
- 값은 문자열을 이어 붙이지 않고 `{}` 자리 표시자로 넣는다.
- 로그에 API 키, 비밀번호 해시, 문서 본문 전체를 남기지 않는다.

## 3. JavaScript·React (frontend)

- ESLint·Prettier 설정을 따른다. 커밋 전에 `npm run lint`가 통과해야 한다. (Prettier: 작은따옴표, 세미콜론, 한 줄 100자)
- 컴포넌트는 PascalCase 파일·함수(`DocumentListPage.jsx`), 훅은 `use`로 시작, 변수·함수는 camelCase로 쓴다.
- 화면 하나는 `pages/`, 여러 화면에서 쓰는 조각은 `components/`, 서버 호출은 `api/`, 공통 함수는 `utils/`에 둔다.
- 서버 호출은 `api/` 함수로만 한다. 컴포넌트에서 `fetch`를 직접 부르지 않는다.
- 비동기 처리는 `async/await` + `try/catch/finally`로 쓰고, 오류는 `error` 상태에 담아 화면에 안내 문구로 보여 준다.
- AI가 만든 요약·키워드·답변 옆에는 `AiBadge`("AI 생성")를 붙인다.

## 4. 테스트

- 기능을 구현하면 정상 케이스와 예외 케이스 테스트를 함께 작성한다(운영계획서 7절).
- 도구: JUnit 5 + AssertJ, 외부 연동(OpenAI 등)은 Mockito로 대신한다. API 테스트는 MockMvc와 메모리 H2를 쓴다.
- 테스트 메서드 이름은 한국어로 "조건_결과" 형태로 쓴다. 예: `빈_파일은_400()`, `요약에_실패해도_문서는_READY로_저장된다()`
- 테스트 하나는 동작 하나만 확인한다. 준비 → 실행 → 확인 순서로 빈 줄을 두어 나눈다.
- 테스트가 개발 DB(`backend/data`)나 실제 OpenAI를 쓰지 않게 한다.
- PR을 올리기 전에 `gradlew test`가 모두 통과해야 한다.

## 5. Git과 PR

### 5.1 브랜치

| 종류 | 이름 | 예 |
| --- | --- | --- |
| 기능 | `feature/F-ID-설명` | `feature/F-03-qa` |
| 수정 | `fix/설명` | `fix/upload-review` |
| 문서 | `docs/설명` | `docs/coding-rules` |

- 항상 최신 `develop`에서 브랜치를 만든다. `main`에는 최종 제출 때만 합친다.
- 브랜치는 작업 단위(기능 하나)로 만든다. 커밋은 한 브랜치에 여러 번 해도 된다.

### 5.2 커밋 메시지

- `[태그] 무엇을 했는지` 형식으로 쓴다. 태그는 기능 ID 또는 종류다.
- 태그: `[F-01]`~`[F-08]`, `[DB]`, `[UI]`, `[설계]`, `[문서]`, `[테스트]`, `[골격]`
- 예: `[F-01] 실패한 업로드의 원본 파일 삭제`, `[문서] 팀 코딩 규칙 확정`

### 5.3 PR과 리뷰

- 코드 변경은 PR로 `develop`에 합친다. 문서만 바꿀 때는 `develop`에 바로 커밋해도 된다.
- PR 설명에는 바뀐 내용, 테스트한 방법, 리뷰 요청 사항을 쓴다. 리뷰 반영 PR은 이전 PR 번호(`#2`)를 적는다.
- **리뷰어 전원이 Approve한 뒤** 작성자가 머지한다. 고칠 점이 있으면 리뷰어는 Request changes를 남긴다.
- 머지 후 브랜치를 지운다.

## 6. AI 코딩 도구

- AI 도구는 저장소의 `CLAUDE.md`를 따른다. 이 문서의 규칙은 CLAUDE.md 코딩 규칙 절에 요약해 둔다.
- AI가 만든 코드도 사람이 읽고, 테스트를 돌려 확인한 뒤 커밋한다.
- AI를 쓴 작업은 `docs/AI_활용_로그`에 프롬프트 요지, 채택·수정·폐기 이유, 검증 결과를 남긴다.
