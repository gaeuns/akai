## 3. 평가 방법

### 3.1 평가 자료

- 문서: 시연 문서 5개(`docs/01~05`, 팀이 쓴 가상 문서). 학사운영규정 PDF 11쪽, 연구비집행지침 PDF 3쪽, 디자인패턴 강의노트 PDF 3쪽, 정보보안 매뉴얼 TXT, 생활불편민원 처리기준 TXT. 샘플 데이터(`db/sample-data.sql`)의 문서는 넣지 않았다.
- 평가 질문(`eval/questions.csv`, 24개): 질문마다 유형(답 있음/답 없음), 정답 핵심어, 근거 문서·쪽을 적었다. 정답과 쪽은 원문(PDF는 쪽별 추출)에서 직접 확인했다.
  - 답 있음 17개: 문서 5개에 3\~5개씩 나눴다.
  - 답 없음 7개: 문서에 전혀 없는 질문 4개(Q18\~Q21)와, 문서에 비슷한 내용은 있지만 물어본 정보는 없는 함정 질문 3개(Q22 콜센터는 평일·토요일만 적혀 있음, Q23 교육 미이수는 접속 제한만 적혀 있음, Q24 Observer는 이름만 나옴)
- 보조 질문(`eval/questions_paraphrase.csv`, 7개): 평가 질문과 같은 정답을 문서와 다른 말로 물었다(F-06 의미 검색 확인용). NF-01 지표 계산에는 넣지 않았다.

### 3.2 채점 규칙 (`eval/evaluate.py`)

- 정답: 답 있음 질문에서 found=true이고, 정답 핵심어가 답변에 모두 들어 있으면 정답이다. 공백과 쉼표는 무시하고, "4분의3 또는 75%"처럼 둘 중 하나만 있어도 된다.
- 근거 표시: found=true인 답변에 근거가 1개 이상 함께 왔으면 표시된 것이다.
- 거절: 답 없음 질문에 found=false("문서에서 찾을 수 없음")로 답했으면 거절이다.
- 근거 일치(참고): 정답 근거 문서·쪽이 근거 목록에 들어 있으면 일치다.
- 채점 규칙 자체는 `python eval/evaluate.py --check`로 확인한다(통과).

### 3.3 실행 환경

- 서버: develop 4edeb17, 로컬 H2 DB, 질문 계정 member01
- AI: gpt-4o-mini(답변), text-embedding-3-small(임베딩), 유사도 기준 0.35
- 실행: 기본 설정(embedding)으로 서버를 켜고 `python eval/evaluate.py --label embedding`, 서버를 `--app.search.strategy=keyword`로 다시 켜고 `--label keyword`로 한 번 더 실행했다.
- 임베딩 측정이 서버 시작 후 첫 질문이라, 조각 24개의 임베딩 계산 시간이 Q01에 들어갔다.

### 5.2 유사도 기준 0.35가 답 있음과 답 없음을 가르지 못함

| 구분 | 1위 유사도 범위 | 기준(0.35) 이상 |
| --- | --- | --- |
| 답 있음 17개 | 0.353 (Q15) \~ 0.677 (Q06) | 17개 |
| 답 없음 7개 | 0.300 (Q20) \~ 0.555 (Q21) | 5개 (Q18 0.412, Q19 0.387, Q21 0.555, Q23 0.404, Q24 0.432) |

- 답 없음 질문 5개가 기준을 넘어 AI가 호출되었고, AI가 "문서에서 찾을 수 없음"으로 답해 거절되었다. CLAUDE.md AI 기능 규칙 2("관련 조각이 없으면 AI를 호출하지 않는다")의 코드 장치는 이 5개에서 작동하지 않았고, 거절은 AI 프롬프트에 기대고 있다.
- 두 범위가 겹쳐(0.353\~0.555) 기준값만 바꿔서는 둘을 나눌 수 없다. 기준을 0.45로 올리면 답 없음은 Q21 하나만 남지만 답 있음 7개(Q03·Q07·Q10·Q13·Q14·Q15·Q16)의 1위 조각도 기준 아래로 떨어진다.
- 키워드 검색은 답 없음 7개 중 4개(Q19·Q20·Q22·Q23)에서 관련 조각을 못 찾아 AI를 호출하지 않았다(0.02\~0.05초).

### 5.3 응답 시간

- 임베딩 검색의 첫 질문(Q01)이 5.76초로 NF-02(5초)를 넘었다. 처음 검색할 때 저장되지 않은 조각 24개의 임베딩을 한 번에 계산하기 때문이다. 이후 질문은 0.28\~3.06초였다.
- 키워드 검색은 평균 0.90초, 최대 3.28초(첫 질문)였다.

### 5.4 표현을 바꾼 질문

- F-06(임베딩)은 "키워드가 달라도 뜻이 비슷한 조각을 찾는다"가 목적이지만, 이 7개에서는 키워드 검색과 정답률이 같았고 맞힌 질문도 달랐다. 두 결과를 합치면 4/7(57%)이 된다.
- 임베딩 검색이 틀린 P04·P05는 0.3초 안에 끝나 AI가 호출되지 않았다. 1위 유사도가 기준 0.35보다 낮았다는 뜻이다. 5.2절과 합치면, 기준 0.35는 표현을 바꾼 답 있음 질문은 걸러 내고 답 없음 질문은 통과시키는 경우가 있다.

### 5.5 측정의 한계

- 평가 질문 24개를 원문을 보고 썼기 때문에 문서와 같은 낱말을 많이 쓴다. 이 때문에 키워드 검색에 유리했을 수 있고, 4.2절 보조 질문을 따로 둔 이유다.
- 질문 수가 적어(답 있음 17개) 1문항이 정답률 약 6%p를 바꾼다.
- 같은 질문도 AI 답변 문장은 실행마다 조금 달라질 수 있다(temperature 0.2). 이번 측정은 각 1회다.

## 7. 개선 제안 (팀 결정 필요)

1. 기본 검색 방식: 이번 평가 질문에서는 키워드 검색이 정답률·거절 장치·속도 모두 앞섰다. 시연 기본값을 keyword로 두고, F-10 화면으로 임베딩을 비교 시연하는 방안을 제안한다.
2. 임베딩 검색 개선: 키워드 결과와 임베딩 결과를 합치는 방식, 또는 기준값을 평가 질문으로 다시 정하는 방식. 5.2절처럼 기준값만으로는 한계가 있다.
3. 조각 분할: 한 조각에 여러 주제가 섞이면 임베딩 검색이 약해진다(5.1절). 조항·소제목 단위로 나누는 방안.
4. 첫 질문 지연: 조각 임베딩을 업로드 때 계산하면 첫 질문 5.76초 문제가 사라진다.
